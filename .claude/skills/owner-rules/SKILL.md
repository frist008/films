# Работа с владельцем (перенесено из памяти Claude в проект, владелец 2026-10-24)

Владелец: «всё по этому проекту должно лежать в проекте, не в глобальных скилах и не в памяти». Личные данные
(профиль, адрес, телефон, аккаунты) — только в `config/private.toml` (`[owner_profile]`, `[accounts]`, в git не попадает);
в тексте — метки `<google.main>`, `<plex.user>` и т.п. Память Claude для проекта не используется — хук
`.claude/hooks/no-memory.sh` блокирует запись туда.

## 1. Внимательность — главный принцип
«Ты не можешь пропустить выполнение чего-либо, что я попросил, и никакой экономии; главный принцип проекта — внимательность».
- Ничего не пропускать, не упрощать, не экономить на запросах, страницах, проверках, токенах. Не удалось — сказать явно
  и записать в PLAN.md.
- Сайты, закрытые от curl (rutracker — Cloudflare, Google Play, аккаунт YouTube), — через Chrome (Claude in Chrome
  залогинен под владельцем). «Не тупи, у тебя есть Chrome».
- Каждый тайтл — полностью, по всем полям.

## 2. Проверять, прежде чем утверждать
Прежде чем сказать владельцу, что работает и какой агент в Chrome, — проверить (задания агентов, процессы, вкладки,
`films.watchdog`), а не отвечать по памяти. Владелец видит каждое окно разрешений Chrome; неточный статус для него — ложь.
Параллельным агентам Chrome — только если без него никак, с перечнем сайтов.

## 3. Вопросы — только через AskUserQuestion
- По-русски, ≤ 4 вопросов за вызов, нумерация «N/M ·» в опросах, категория предмета. Не текстом в ответе и не в поле `ask`
  итоговой карточки (с телефона он её не видит).
- Только вопросы по существу; никаких «делать / не делать» по тому, что уже в плане или уже попросил
  («пока не закончишь — никаких остановок и опросов»).
- Ссылки в вопросе не кликабельны, а текст перед вопросом с телефона не виден: гиперссылка `[текст](url)` — в итоговом
  сообщении хода, вопрос по ней — позже (хук `survey-guard.sh` отклоняет URL в вопросах).
- Прочие правила опросов (сезоны галочками, рейтинг только IMDb, без «ранние части») — скил `owner-survey`, хук `survey-guard.sh`.

## 4. Всё — в план, всё работающее — в скилы
- Каждое сообщение владельца — первым делом в PLAN.md (хук `plan_guard.py` сам кладёт во «Входящие»; разобрать в R-пункт).
- Удачный приём (сопоставление, пакетная работа в Chrome, формат опроса) — сразу в нужный `.claude/skills/*/SKILL.md`
  или docs/, чтобы любой аккаунт мог повторить. Новое правило — CLAUDE.md «Решения».
- Выполненное — проверить и перенести в PLAN-done.md; этап — на GitHub (Stop-хук проверяет).
- **Приостанавливаешь что-то — сначала запиши в PLAN.md, что и где остановлено** (владелец, 2026-10-24: «чтобы не забыть, что остановил»), потом переключайся.
- **План работ — с зависимостями** (владелец, 2026-10-25: «Ты смотрел, какие пункты какие триггерят, когда план давал?»):
  прежде чем показать план, для каждого шага выписать, что он меняет и какие шаги после него надо повторить; шаг, который
  меняет данные (магазины → желаемое → баллы, новые тайтлы → метаданные), — раньше пересборки таблицы и плейлистов;
  проверки — до записи, а не после. Нумерация — порядок выполнения, параллельные шаги — буквы (1а, 1б, 1в).
- **Важных людей, франшизы, «не интересно», ответственных — решает только владелец** (2026-10-25: «Ты же сам важных людей
  не добавлял? Только я могу решать, кто важный» — Нолан и Гай Ричи были добавлены по колонке старой таблицы без вопроса).
  Догадку — спросить, не записывать; у записи — его слова (хук `people-guard.sh` для `config/people.toml`).
- **Агенты отчитываются процентом и прогнозом** (владелец, 2026-10-25): в задании каждому фоновому агенту — писать в
  `data/logs/agent_<имя>.log` не реже раза в 10 минут `PROGRESS N% ETA HH:MM — <шаг>`, в конце `AGENT_<ИМЯ>_OK`; сторож
  (`films.watchdog`, таймер каждые 10 минут) показывает владельцу «кто, сколько %, когда закончит».
- **В план — только сделанное или реально запущенное** (владелец, 2026-10-25: «Всё сделал, выходит?» — в плане стояло «агент,
  19:30», а агент не был запущен): пишешь «запускаю / агент» — в том же шаге запуск и путь к логу `data/logs/….log`
  (Stop-хук `plan_guard.py` проверяет, что лог есть). Отчёт «всё сделано» — только после сверки с PLAN.md: открытые пункты
  до версии перечислить честно.
- **План вычищать по правилам, не накапливать**: каждый закрытый пункт — в PLAN-done.md сразу после проверки; раз в этап —
  пройти все «- [ ]» и закрыть сделанное (агент-аудит по коду и базе), в PLAN.md — только открытое.
- **Просмотренное — нигде, кроме прямых просьб**: в вопросах владельцу (трейлеры, опросы) просмотренных тайтлов не бывает.
- **Убирать за собой мусор — всегда, в конце каждого этапа** (владелец, 2026-10-25: «Не забудь удалить за собой мусор от трейлеров», «записать в скил … чтобы ты не забывал чистить мусор за собой в принципе»). Этап закончен — до отчёта и коммита пройти чек-лист:
  1. скачанное для проверки (звук и видео трейлеров `data/cache/trailer_audio/`, `*.part`, `*.ytdl`, `*.webm`, `*.m4a`, `*.wav`), временные файлы yt-dlp / ffmpeg в `%TEMP%`;
  2. пробные копии базы и большие промежуточные файлы агентов в scratchpad сессии (`films_copy.db`, `films_before.db`, `*.pkl`, выгрузки) — когда ни один агент ими уже не пользуется;
  3. одноразовые скрипты-черновики — их удачную логику сначала перенести в код проекта и скил, потом удалить черновик;
  4. вкладки Chrome (и пустые «Новая вкладка»), остановленные фоновые процессы (мост, циклы), таймер-сторож — если фоновых больше нет;
  5. в `data/cache/locks/wip.txt` — только файлы, которые агенты правят прямо сейчас.
  **Удалять только СВОИ файлы, по именам** — никаких масок вроде `scratchpad/*.py`: папка общая, 2026-10-25 агент так снёс
  скрипты другого работающего агента. Свои временные файлы — с префиксом своего имени (`<агент>_*.py`).
  Не трогать: базу и её строки, кэши, которые проект читает повторно (вердикты звука `data/cache/youtube/audio_checks.jsonl`, `release_raw`, `tmdb_raw`, `data/cache/imdb_specs/`), отчёты и логи, файлы владельца на дисках (их — только по его просьбе и в корзину). Агентам в задании — то же правило, а в отчёте — список удалённого (пути, сколько, размер). Владельцу в итоге — коротко, что убрано.

## 5. Работать до конца плана

**Не откладывать «на следующее обновление»** (владелец, 2026-10-25: «Когда я скажу обновить базу, там кроме стандартных операций должен быть вопрос только про сортировку. Остальные мы должны решить до 1.0.0»): туда идёт только то, что владелец сам туда отнёс; вопросы и доработки решаются в текущей итерации, до выпуска версии.
«Пока не закончишь — никаких остановок или опросов на делать / не делать», «не закончишь весь план». После шага — следующий
открытый пункт плана; независимое — параллельно (фоном, с семафорами `films/locks.py`). «Всё делай параллельно и следи, чтобы закончилось успешно, и перезапускай» (2026-10-24): фоновая цепочка заканчивается маркером `echo NAME_OK` в логе; нет маркера / упало / зависло (сторож `films.watchdog`) → разобраться, перезапустить, записать в PLAN.md. **Отчёт агента — не повод гонять его скрипты заново** (владелец, 2026-10-24: «надеюсь, агенты умеют отчитаться о выполнении, чтобы ты не грузил скрипты по второму кругу»): агент в конце пишет отчёт (цифры до/после, что не вышло и почему) и маркер `AGENT_*_OK` в `data/logs/agent_*.log`; проверка после него — только чтением (запросы к БД, логи, `git diff`), перезапуск — лишь того, что агент сам назвал упавшим. Файлы, которые агент ещё правит, — в `data/cache/locks/wip.txt` (Stop-хук их не требует коммитить; после проверки — коммит и убрать строку).

## 6. Plex и Google TV — хронология владельца
- **YouTube — сначала спросить, свободен ли** (владелец, 2026-10-26: «ютуб пока занят … если нужен будет ютуб, то спроси
  свободен ли он, запиши в скил и хук, остальное всё можешь делать»): перед любой работой в браузере на youtube.com —
  AskUserQuestion «YouTube сейчас свободен?» («Да, свободен» / «Нет, занят»); хук `youtube-guard.sh` иначе не пустит.
  Занят — всё остальное (без YouTube) делать, что можно — фоном.
- **Буфер обмена — владельца, не писать в него** (2026-10-26: «не пиши в буфер обмена! запомни»): текст, который владелец
  должен вставить, — в файл, путь — в сообщении; хук `clipboard-guard.sh` (тест `tests/test_clipboard_guard.py`).
- **Ничего глобального** (владелец, 2026-10-26: «в мемори глобальной ничего не должно быть что касается этого проекта!»):
  память Claude, глобальные скилы, хуки, агенты, команды, `~/.claude/CLAUDE.md` и `settings.json` любого профиля
  (`~/.claude`, `AppData/Roaming/MultiDeskClaude-Profiles/*/.claude`) не трогать — хук `no-memory.sh`, тест `tests/test_no_memory_hook.py`.
- «Просмотрено» в Plex — только по словам владельца («я видел X») или его постоянному поручению (перенос из Jellyfin).
  Купил, скачал, было в старой таблице, догадка — не повод.
- Никогда не отмечать повторно уже просмотренное (каждая отметка пишет сегодняшнюю дату и ломает хронологию: «не трогай
  мои фильмы, где была чёткая история»). Сезон — только по сериям, пропуская просмотренные. Подозрение на ущерб —
  сообщить и спросить, прежде чем удалять записи истории. Закреплено кодом: `films/sources/plex_guard.py`, хук `plex-guard.sh`.
- Кнопка «Хочу посмотреть» Google TV переключается — нажатие на добавленном удаляет и теряет дату. Только
  `films/browser/gtv_watchlist_guard.js` (`__gtvGuard.add`), цикл — `films/browser/gtv_loop.js`; хук `gtv-guard.sh`.
  Принадлежность к списку — по состоянию кнопки, не только по `store_items`.

- **Опознавать только то, что реально есть** (владелец, 2026-10-25: «Если в Plex нет и удалено, то не надо искать, что это. Смотрим только по реальному наличию»): просмотр в истории Plex без файла (файл удалён, Plex не опознал) — не выяснять и не спрашивать; опознаётся только то, что лежит в Plex / Jellyfin / на диске E сейчас.
- **Франшизы из списков владельца** (2026-10-25: «Всё из моих списков — следить»; «Следить за всем, что я видел. Не надо спрашивать»): франшиза, часть которой есть в его списках или которую он видел, — «Все годы» без вопроса. Спрашивать только то, что не из его списков и не видено.

## 7. Списки владельца — сопоставление
- Русские названия в его списках — ровно как в заголовках раздач rutor (первый источник). Варианты в вопросах — полные
  русские заголовки раздач rutor («RU / второе RU / EN (год)»), не английские ярлыки.
- «%» в строке — Rotten Tomatoes на момент записи: сверять с RT кандидатов.
- Дата сообщения ≈ когда раздача была на rutor → фильм вышел за несколько месяцев до этого; если даты/годы уже решают
  выбор — решить самому, не спрашивать. Код: `films.kostya_list verify` (точное совпадение RU-названия с rutor).

## 8. Аккаунты и секреты
Все аккаунты Google в Chrome — владельца (`config/private.toml`: `[google]`, `[accounts]`). Таблица — на `<google.main>`,
проект GCP `films-db` (OAuth) — на `<google.cloud>`; секреты — заметка Google Keep «films — секреты» на `<google.cloud>`,
в git никогда (репозиторий открытый). Ключи в веб-формы не вводить — значения вставляет владелец. Подробно — docs/google-setup.md.
Профиль владельца (`[owner_profile]`) — только для форм, которые он сам просит заполнить; чего нет — спросить, не выдумывать.

## 9. Публичный репозиторий: что можно, что нельзя (ревью 2026-10-24, ответы владельца)

**Скрывать — только после вопроса владельцу** (2026-10-24): прежде чем что-либо скрыть, удалить или хэшировать «как личное», — AskUserQuestion: что скрывать, а что нет (по пунктам). Сам не решать. Откатывать сделанное — тоже только спросив («Откатываешь не спросив меня, нужно или нет?»). Личные видео владельца (свои ролики, проекты монтажа): в git — никогда (копия `backup/` их исключает целиком), в локальной базе — временно, удалить 2026-10-31 (ответ владельца 2026-10-25). Ошибки 2026-10-24: удалил и захэшировал, не спросив; потом откатил, не спросив.
- **Нельзя в git:** секреты (`.env`, `secrets/`, Plex-токен), значения `config/private.toml`, пути к личным файлам владельца
  (проекты монтажа, ролики, рабочие папки, загрузки телефона), имя пользователя Windows. Копия базы `backup/` делается
  `films/backup.py`: `_redact` прячет у файлов не-фильмов (disk_files, qbt_torrents, нераспознанные plex_items /
  jellyfin_items) пути и названия → «диск:#хеш», а путь `…/Users/<имя>` → `<user>`. Локальная БД остаётся полной.
- **Можно (владелец решил):** имена близких и «Костя» без фамилий, логин GitHub как есть, слово «Vegas» («не важно»),
  просмотренное и покупки.
- `python -X utf8 -m films privacy-check` (pre-push): значения private.toml **без учёта регистра**, почты, ключи, пути с
  настоящим именем пользователя Windows; при FAILED — не пушить, исправить.
- Ревью чувствительных данных — фоновым агентом по всей истории (`git log -p`), отчёт `data/cache/review_sensitive.md`.
- Чистка истории — только по «да» владельца: запасная ветка → `git filter-branch --index-filter` (заменить файлы
  очищенными версиями во всех коммитах) → проверка каждого коммита (`git grep` по шаблонам) → `git push --force-with-lease`. Решения владельца 2026-10-25 по копии на GitHub: имя пользователя Windows → «<user>», пути/имена файлов дисков, которые не фильмы, → код, торренты без фильма → код; нераспознанные файлы Plex/Jellyfin не скрывать, а опознавать («ты не имеешь права такое пропускать»).

- **Баг — только со стражем в коде** (владелец, 2026-10-25: «Баги настолько часто, что исправлять надо кардинально»): любой баг, который заметил владелец, — строка в `docs/bugs.md` (его слова, причина, страж) в том же ходе; страж — хук, тест или проверка в модуле, проверенные на повторе. Правило в скиле без кода стражем не считается; Stop-хук `plan_guard.py` не пропустит строку без существующего стража.
- **Отчёт сторожа владелец видит сам**: раз в 10 минут хук `watchdog-tick.sh` показывает ему системным сообщением, кто работает (%, ETA, шаг, зависшие); в следующем своём сообщении — повторить одной-двумя строками.
