# Работа с владельцем (перенесено из памяти Claude в проект, владелец 2026-10-24)

Владелец: «всё по этому проекту должно лежать в проекте, не в глобальных скилах и не в памяти». Личные данные
(профиль, адрес, телефон, аккаунты) — только в `config/private.toml` (`[owner_profile]`, `[accounts]`, в git не попадает);
в тексте — метки `<google.main>`, `<plex.user>` и т.п. Память Claude для проекта не используется — хук
`.claude/hooks/no-memory.sh` блокирует запись туда.

## 1. Внимательность — главный принцип
«Ты не можешь пропустить выполнение чего-либо, что я попросил, и никакой экономии; главный принцип проекта — внимательность».
- Ничего не пропускать, не упрощать, не экономить на запросах, страницах, проверках, токенах. Не удалось — сказать явно
  и записать в PLAN.md.
- Сайты, закрытые от curl (rutracker — Cloudflare, Google Play, аккаунт YouTube), — через Chrome (Claude in Chrome
  залогинен под владельцем). «Не тупи, у тебя есть Chrome».
- Каждый тайтл — полностью, по всем полям.

## 2. Проверять, прежде чем утверждать
Прежде чем сказать владельцу, что работает и какой агент в Chrome, — проверить (задания агентов, процессы, вкладки,
`films.watchdog`), а не отвечать по памяти. Владелец видит каждое окно разрешений Chrome; неточный статус для него — ложь.
Параллельным агентам Chrome — только если без него никак, с перечнем сайтов.

## 3. Вопросы — только через AskUserQuestion
- По-русски, ≤ 4 вопросов за вызов, нумерация «N/M ·» в опросах, категория предмета. Не текстом в ответе и не в поле `ask`
  итоговой карточки (с телефона он её не видит).
- Только вопросы по существу; никаких «делать / не делать» по тому, что уже в плане или уже попросил
  («пока не закончишь — никаких остановок и опросов»).
- Ссылки в вопросе не кликабельны, а текст перед вопросом с телефона не виден: гиперссылка `[текст](url)` — в итоговом
  сообщении хода, вопрос по ней — позже (хук `survey-guard.sh` отклоняет URL в вопросах).
- Прочие правила опросов (сезоны галочками, рейтинг только IMDb, без «ранние части») — скил `owner-survey`, хук `survey-guard.sh`.

## 4. Всё — в план, всё работающее — в скилы
- Каждое сообщение владельца — первым делом в PLAN.md (хук `plan_guard.py` сам кладёт во «Входящие»; разобрать в R-пункт).
- Удачный приём (сопоставление, пакетная работа в Chrome, формат опроса) — сразу в нужный `.claude/skills/*/SKILL.md`
  или docs/, чтобы любой аккаунт мог повторить. Новое правило — CLAUDE.md «Решения».
- Выполненное — проверить и перенести в PLAN-done.md; этап — на GitHub (Stop-хук проверяет).
- **Приостанавливаешь что-то — сначала запиши в PLAN.md, что и где остановлено** (владелец, 2026-10-24: «чтобы не забыть, что остановил»), потом переключайся.

## 5. Работать до конца плана
«Пока не закончишь — никаких остановок или опросов на делать / не делать», «не закончишь весь план». После шага — следующий
открытый пункт плана; независимое — параллельно (фоном, с семафорами `films/locks.py`). «Всё делай параллельно и следи, чтобы закончилось успешно, и перезапускай» (2026-10-24): фоновая цепочка заканчивается маркером `echo NAME_OK` в логе; нет маркера / упало / зависло (сторож `films.watchdog`) → разобраться, перезапустить, записать в PLAN.md.

## 6. Plex и Google TV — хронология владельца
- «Просмотрено» в Plex — только по словам владельца («я видел X») или его постоянному поручению (перенос из Jellyfin).
  Купил, скачал, было в старой таблице, догадка — не повод.
- Никогда не отмечать повторно уже просмотренное (каждая отметка пишет сегодняшнюю дату и ломает хронологию: «не трогай
  мои фильмы, где была чёткая история»). Сезон — только по сериям, пропуская просмотренные. Подозрение на ущерб —
  сообщить и спросить, прежде чем удалять записи истории. Закреплено кодом: `films/sources/plex_guard.py`, хук `plex-guard.sh`.
- Кнопка «Хочу посмотреть» Google TV переключается — нажатие на добавленном удаляет и теряет дату. Только
  `films/browser/gtv_watchlist_guard.js` (`__gtvGuard.add`), цикл — `films/browser/gtv_loop.js`; хук `gtv-guard.sh`.
  Принадлежность к списку — по состоянию кнопки, не только по `store_items`.

## 7. Списки владельца — сопоставление
- Русские названия в его списках — ровно как в заголовках раздач rutor (первый источник). Варианты в вопросах — полные
  русские заголовки раздач rutor («RU / второе RU / EN (год)»), не английские ярлыки.
- «%» в строке — Rotten Tomatoes на момент записи: сверять с RT кандидатов.
- Дата сообщения ≈ когда раздача была на rutor → фильм вышел за несколько месяцев до этого; если даты/годы уже решают
  выбор — решить самому, не спрашивать. Код: `films.kostya_list verify` (точное совпадение RU-названия с rutor).

## 8. Аккаунты и секреты
Все аккаунты Google в Chrome — владельца (`config/private.toml`: `[google]`, `[accounts]`). Таблица — на `<google.main>`,
проект GCP `films-db` (OAuth) — на `<google.cloud>`; секреты — заметка Google Keep «films — секреты» на `<google.cloud>`,
в git никогда (репозиторий открытый). Ключи в веб-формы не вводить — значения вставляет владелец. Подробно — docs/google-setup.md.
Профиль владельца (`[owner_profile]`) — только для форм, которые он сам просит заполнить; чего нет — спросить, не выдумывать.
