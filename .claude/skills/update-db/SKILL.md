# Обновление базы

Главный принцип — внимательность: не пропускать ни одного шага и ни одного тайтла. Если шаг не удался —
сообщить владельцу и записать в PLAN.md. Сначала прочитай CLAUDE.md и PLAN.md: если этап ещё не реализован
скриптом, выполни шаг вручную по описанию в CLAUDE.md и отметь это в отчёте.

Нет `.env` (TMDB-ключ) или `secrets/` — взять из заметки Google Keep «films — секреты» аккаунта <google.cloud>
(`docs/google-setup.md`). В git секреты не кладутся никогда.

**Точки отсчёта**: `python -X utf8 -m films sync-status` — когда и до какого места синхронизирован каждый источник
(`sync_state`: rutor_listing, rutor_pages, plex_library, plex_history, plextv_history, stores, tmdb, rt, imdb_datasets, …).
Брать только новое после курсора; после успешного шага — `films.db.mark_sync(conn, source, cursor, details)`.

**Фоновые агенты/команды** (долгие шаги, параллельные источники): после запуска — взвести проверку раз в 30 минут
(`CronList` → нет → `CronCreate` «13,43 * * * *»), см. CLAUDE.md «Сторож фоновых агентов». Все закончили → `CronDelete`.

## Шаги (по порядку)

1. `python -X utf8 -m films update --start` — открыть прогон (`runs`), запомнить run_id.
2. **rutor**: собрать раздачи по категориям 1/4/7 за все годы из `config/settings.toml`.
   Каждый поисковый срез должен давать < 2000 результатов, иначе дробить дальше. Новые раздачи и
   изменившиеся (сиды, размер) записать; для новых — скачать страницу раздачи в `release_raw` и разобрать.
   Раздачи только с DV Profile 5 не сохранять.
3. **Сопоставить** новые раздачи с тайтлами (IMDb-ссылка в описании → названия+год). Неоднозначное →
   `match_issues`, показать владельцу в отчёте.
4. **Новые тайтлы** — метаданные (названия RU/UK, страны, жанры, длительность, студии, роли, режиссёр,
   сценарист, дата выхода), IMDb-рейтинг, RT (оба рейтинга; искать по оригинальному, латинскому, RU, UK названию),
   IMAX / мастер 2K-4K / бюджет / постер (IMDb GraphQL, без браузера): `python -X utf8 -m films.sources.imdb_specs run`;
   новое без TMDB — `python -X utf8 -m films enrich`, рейтинги — `films ratings imdb` и `films ratings rt`;
   полнота по полям — `python -X utf8 -m films.audit` (в отчёт владельцу);
   франшизы за все годы — `python -X utf8 -m films.franchise_releases` (потом снова pages/parse/match);
   русский трейлер: `python -X utf8 -m films.sources.youtube trailers` (короче 1:30 — тизер: штраф, ищется длиннее; не нашлось — `trailer_ru_check = teaser_only`), затем **аудит** `python -X utf8 -m films.trailer_audit --apply` (целые фильмы > 5 мин, недоступное в UA, трейлер другого фильма — снимаются; тизеры и несовпадение названий — в отчёт `data/cache/trailer_audit.json`);
   русский трейлер: `python -X utf8 -m films.sources.youtube trailers` (долго — фоном + сторож). Трейлер
   принимается, только если на странице ролика YouTube подтвердил русскую речь (язык дорожки / автосубтитров) либо
   название говорит «дубляж/озвучка»; русские субтитры к оригиналу и украинские трейлеры — отдельные находки, не
   трейлер. Правила — `docs/youtube.md`; спорные — `data/cache/youtube/ambiguous.jsonl`. Затем **обязательно** скил
   `trailer-check` (`films.sources.trailer_lang check --unconfirmed`): трейлеры без подтверждённой русской речи
   проверяются по субтитрам, альтернативам и звуку (распознавание речи).
5. **Перепроверить рейтинги** тайтлам, вышедшим за последние 90 дней, и тем, у кого рейтинга не было.
6. **rutracker** (Chrome, залогинен <rutracker.user>): для тайтлов, у которых на rutor нет 4K, нет HDR/DV или
   нет дубляжа — поискать там (по оригинальному и русскому названию), сохранить найденное.
7. **Plex и Jellyfin**: пересканировать все библиотеки Plex (скачано + качество файла), просмотренное (библиотеки +
   история plex.tv <plex.user>); затем `python -X utf8 -m films link all` — Jellyfin (копия БД: файлы с id и
   просмотры <jellyfin.user>), Plex (файлы без id опознаются через Jellyfin / имя шоу / папку), магазины.
   Всё просмотренное, купленное и скачанное заводится тайтлами за любые годы; на Главную без раздачи не попадает.
   Неопознанные шоу — `data/plex_show_map.json` (статусы `ambiguous`/`not_found`; `auto_popular` показать владельцу).
   **Каждый файл на дисках** (R85): затем `python -X utf8 -m films disks scan` — все видеофайлы C–G (только чтение) →
   `disk_files` → тайтлы (.nfo → `[tmdbid-N]` → Plex/Jellyfin по пути → qBittorrent → имя; ручные — `data/disk_map.json`);
   скачанное = не просмотрено, в опрос «что видел» не идёт. Отчёт `data/cache/disk_files_report.json`: несопоставленное
   по папкам, «на диске, но не в Plex/Jellyfin», допущения (S1 assumed, по голосам) и конфликты метаданных Plex/Jellyfin/.nfo
   (`data/cache/disk_conflicts.json`) — показать владельцу.
   **Обязательно** (владелец, 2026-10-23): просмотренное в Jellyfin отметить в Plex — `python -X utf8 -m films watched
   from-jellyfin` (сначала `--dry-run`; фильмы целиком, серии поштучно, уже отмеченное в Plex пропускается). Всё,
   что не `confirmed`, — в отчёт владельцу.
7а. **Очередь qBittorrent** (R47): `python -X utf8 -m films.sources.qbittorrent` — раздачи в клиенте (`BT_backup`),
   недокачанные = «В очереди» (зелёная строка, белый текст). Несопоставленное — в отчёт (личные записи — `ignored`).
   **Список «хочу»** (R48): пункты с `russian = true` (наши сериалы, напр. «Интерны») ищутся в rutor «Наши сериалы» (категория 16); `python -X utf8 -m films.watchlist resolve` → `releases` → `films rutor pages/parse` →
   `films match` (раздачи за все годы, в т.ч. аниме cat 10). **Широкий поиск по названию** (все годы) — сразу после
   него `python -X utf8 -m films.kostya_list relevant`: страницы качать только для строк, где название раздачи = название
   нужного тайтла и год ±1 (иначе короткие названия дают десятки тысяч чужих раздач); остальным `page_skip = 1`. **Ответственные**: `python -X utf8 -m films.responsible all`.
7а-2. **Здоровье** (R52, R53): `python -X utf8 -m films.health` — мёртвые папки библиотек Plex/Jellyfin, дубли очереди
   и уже скачанное в очереди. Всё найденное — вопросы владельцу через AskUserQuestion (оба имени файла, размеры, папки).
7б. **Франшизы** (`config/franchises.toml`, таблица `franchise_members`): обновить состав вселенных (Wikidata/Википедия/
   fandom), найти раздачи новых и старых произведений выбранных вселенных за все годы (с учётом `from_year`),
   поставить их наверх; в отчёте отдельный блок «новое во франшизах». Команды и правила источников — `docs/franchises.md`
   (`films.franchise resolve|report`); строки `confidence='review'` наверх не поднимаются — показать владельцу.
   Франшизы с `anime = true`: искать раздачи и в категории rutor «Аниме» (cat 10) и на rutracker; другое аниме не брать (R44).
7в. **Игры владельца → экранизации** (R36): `python -X utf8 -m films.sources.games collect`, затем `adaptations`, `report`
   (`docs/games.md`). Новые экранизации, которых нет в `config/franchises.toml`, — **сразу добавить** со `scope = "all"`, `source = "games"`
   (правило владельца: по экранизациям его игр не спрашивать); фан-фильмы/документалки — только `review`.
8. **Новинки и ответственные** (R99, владелец 2026-10-24) — `films/fresh.py`:
   - «новое» = **первая** раздача тайтла на rutor не раньше `[fresh] since` (2026-01-01; ручные списки владельца сделаны до НГ 2026).
     Год выхода не важен; дубль или пересборка в лучшем качестве тайтла, который был на rutor раньше, — не новое;
   - новые фильмы с большим из двух баллов RT ≥ 90 → ❤️ (плейлист «Костя Хочет»), 80–89 → 💛 («Вероятно хочу») — та же отметка,
     что в списке владельца; балл учитывается при ≥ 20 рецензиях критиков / ≥ 250 оценках зрителей (`python -X utf8 -m films.fresh`);
   - Дима (комедия 1-м/2-м жанром) и Яна (мультфильмы, без DC/Marvel/Марио) — только **полнометражные фильмы** (≥ 60 мин), новые → сразу
     (`auto`), старые — предположения; сериалов у ответственных нет;
   - сортировка — **баллами** (`[sort.weights]`, владелец: «баллы за каждый признак»), плейлисты — в порядке таблицы, франшизы рядом,
     продолжения — в плейлисте первого фильма (`playlist_notes.all_members`).
   - **Дата последнего обновления**: в конце прогона `films.db.mark_sync(conn, 'update_db', <сегодня>)`; в начале — прочитать её
     (`films sync-status`) и в отчёте показать всё, что появилось на rutor после неё.
8б. **Лист «Купить»** (владелец, 2026-10-24, часть обновления): просмотренное, не купленное, но продающееся на YouTube (UA). Для каждого ролика — цены **покупки** по качествам (`ypc/get_offers`, раздел «Купить»: Ультравысокое = 4K, Высокое = HD, Стандартное = SD) → `python -X utf8 -m films.store_watch buy <файл>` (`vid|ru+en|uhd=цена/старая;hd=…`). Цена = лучшее доступное качество; прокат и худшее качество не учитываются. Порядок листа: с русской озвучкой → с украинской → остальные, внутри — по цене (`sheet._buy_rows`). Новые просмотренные — сначала поиск в YouTube (`store_watch`, R94).
8а. **Плейлисты**: `python -X utf8 -m films.playlist_notes desired` (проверяет все правила; трейлер 1:30–5:00 и играет в UA) → загрузить
   `data/cache/playlists_desired.js` во вкладку youtube.com как есть (хук `playlist-guard.sh`) → синхронизация (скил responsible-playlist) →
   `python -X utf8 -m films.playlist_notes build` (описания к каждому видео).
9. **Апгрейды**: для скачанного сравнить с лучшей раздачей → события `upgrade_available`.
10. Скил `rebuild-sheet` (сначала считать пометки владельца, потом пересоздать таблицу).
11. Плейлисты (Дима, Яна, «Костя Хочет», «Вероятно», «Возможно») — скил `responsible-playlist`, порядок работы оттуда (`desired` → `playlist_sync.js` → сверка). После этого шага (и в любом прогоне, где менялись плейлисты или просмотренное) — `python -X utf8 -m films.playlist_notes build` (готовые описания плейлистов, R68).
12. **Бэкап на GitHub** (открытый репозиторий владельца, создан 2026-10-24): `python -X utf8 -m films.backup export`
    (текстовая копия БД в `backup/`, без кэшей сторонних сайтов) → `git add -A` → коммит → `git push` (SSH-ключ машины уже
    в аккаунте владельца; хук pre-push запускает `films privacy-check` — при «FAILED» не пушить, а убрать личное).
13. `python -X utf8 -m films update --finish` и отчёт владельцу.

## Отчёт владельцу (обязательно)

- сколько новых раздач / новых тайтлов (по категориям и годам);
- **вышло лучшее качество** (BDRemux, 4K, DV, HDR10+) для интересных тайтлов;
- **вышел дубляж** там, где его не было;
- **апгрейды скачанного**: что у владельца → что доступно;
- новые просмотренные (ушли из Главной);
- новые тайтлы Димы;
- проблемы: несопоставленные раздачи, тайтлы без рейтинга/трейлера, ошибки источников;
- новые повторяющиеся типы метаданных, которых нет в схеме, — спросить, сохранять ли.
