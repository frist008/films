# Обновление базы

Главный принцип — внимательность: не пропускать ни одного шага и ни одного тайтла. Если шаг не удался —
сообщить владельцу и записать в PLAN.md. Сначала прочитай CLAUDE.md и PLAN.md: если этап ещё не реализован
скриптом, выполни шаг вручную по описанию в CLAUDE.md и отметь это в отчёте.

Нет `.env` (TMDB-ключ) или `secrets/` — взять из заметки Google Keep «films — секреты» аккаунта <google.cloud>
(`docs/google-setup.md`). В git секреты не кладутся никогда.

**Точки отсчёта**: `python -X utf8 -m films sync-status` — когда и до какого места синхронизирован каждый источник
(`sync_state`: rutor_listing, rutor_pages, plex_library, plex_history, plextv_history, stores, tmdb, rt, imdb_datasets, …).
Брать только новое после курсора; после успешного шага — `films.db.mark_sync(conn, source, cursor, details)`.

**Фоновые агенты/команды** (долгие шаги, параллельные источники): после запуска — взвести проверку раз в 30 минут
(`CronList` → нет → `CronCreate` «13,43 * * * *»), см. CLAUDE.md «Сторож фоновых агентов». Все закончили → `CronDelete`.

## Шаги (по порядку)

0. **Сначала — раздел PLAN.md «Версии»**: там всё, что отложено до этого прогона (вопросы владельцу,
   ждущие клики в Chrome, перепроверки). Выполнить по списку вместе с шагами ниже, сделанное — в PLAN-done.md.
1. `python -X utf8 -m films update --start` — открыть прогон (`runs`, kind `update_db`), запомнить run_id. Команда снимает
   «снимок начала» (`data/cache/update_runs/run_<id>_start.json`: тайтлы с раздачами, лучшая озвучка/HDR/4K/BDRemux, что
   показано на Главной, апгрейды скачанного, просмотренное, ответственные, `sync_state`) — с ним `--finish` сравнивает
   конец прогона. Около минуты (`rank.compute`, как при пересборке таблицы). Открытый прогон уже есть → отказ; прогон
   упал и не закрыт → `--start --force` (старый останется в `runs` со статусом `abandoned`).
2. **rutor**: собрать раздачи по категориям 1/4/7 за все годы из `config/settings.toml`.
   Каждый поисковый срез должен давать < 2000 результатов, иначе дробить дальше. Новые раздачи и
   изменившиеся (сиды, размер) записать; для новых — скачать страницу раздачи в `release_raw` и разобрать.
   Раздачи только с DV Profile 5 не сохранять.
   **Правила раздач из опроса** (владелец, 2026-10-25; разбор — `films/parse/rutor.py` `_release_rules`, запись —
   `films/sources/rutor.py` `store_rules`, выбор лучшей — `films/rank.py` `release_key`): в БД по каждой раздаче —
   встроенная реклама (`has_ads`, ниже), локализованный видеоряд (`localized_video`, выше), 3D, TS/TC/CAM (картинка или
   звук: «звук с TS», Line = «Чистый звук», CAMRip), ремастер/реставрация (Criterion, Arrow, BFI, Remastered — выше всего
   своего и меньшего разрешения, не-ремастеры этого качества не показываются), официальный/неофициальный дубляж
   (`dub_official`; список неофициальных студий — `config/settings.toml [dub_unofficial]`), ч/б / колоризация (цветное выше;
   «ч/б» в названии раздачи, ещё и по IMDb `titles.color`), 60 fps (в названии раздачи), КПК / телефон, озвучка 18+.
   **3D, TS/TC/CAM и КПК исключаются** — строка в `excluded_releases` (reason `is_3d` / `cam` / `kpk`; ничего не удаляется;
   если после правки парсера раздача уже не подходит — reason `lifted:…`). После правки парсера — `python -X utf8 -m
   films.sources.rutor reparse` (все кэшированные страницы, ~5 мин), после правки списка студий — `... rutor rules` (из
   сохранённого разбора, без страниц). Отчёт пишет, сколько раздач исключено по каждому правилу.
3. **Сопоставить** новые раздачи с тайтлами (IMDb-ссылка в описании → названия+год): `python -X utf8 -m films match`.
   Неоднозначное → `match_issues`, показать владельцу в отчёте.
   **Неопознанное — в таблицу без данных** (владелец, 2026-10-25: «Добавлять в таблицу просто без данных, раз не удаётся
   найти»; `films/tracker_only.py`, вызывается тем же `films match` и `films.encountered` после `link_exact_names`):
   раздача, которую не опознали ни IMDb, ни TMDB (открытая проблема `no_imdb_not_found` / `no_imdb_ambiguous` /
   `tmdb_no_title` / `season_year_mismatch`), получает тайтл только из данных трекера — фильм или строка на каждый сезон
   из названия, названия RU / оригинальное / латинское, год (у пачки сезонов первый сезон — первый год, последний —
   последний), страны / жанры / студии / длительность / премьера / число серий, если страница их пишет; без IMDb/TMDB id
   и рейтингов; `titles.tracker_only = 1`, `tracker_meta` (раздачи, проблема и кандидаты сопоставления, франшиза),
   `release_titles.how = 'tracker_only'`, проблема в `match_issues` закрывается. **Не делается** для пачек фильмов,
   исключённых раздач (DV5, 3D, TS/TC/CAM, КПК), аниме вне аниме-франшиз владельца (по названию), раздач до `year_from`,
   если их нет в qBittorrent (R162) и они не из аниме-франшизы владельца. У `tmdb_no_title`-пачки сезоны, которые уже есть
   опознанными тайтлами того же сериала, связываются с ними (`tracker_only_known_season`). В таблице такие строки — как
   любые: без рейтинга правило «IMDb < 5» их не прячет, фильтр озвучки, год и «мультсериал» действуют; пустые колонки
   пустые, в ячейке «Ссылки» — «нет в TMDB/IMDb — данные только с трекера»; постер — с самой страницы раздачи (шаг 4).
   **Каждый прогон сопоставления пробует опознать их заново** (тот же `match.match_one`: датасеты IMDb обновлены этим
   прогоном, поиск TMDB — кэш ≤ 30 дней; фильм — ещё и точное имя + год среди опознанных; строку, которую пробовали в
   последние 20 ч, пропускает, `python -X utf8 -m films.tracker_only run --force` — все сразу). Опознана → раздача
   связывается с настоящим тайтлом (`how` «… from-tracker_only-<id>»), старая связь становится `wrong_link: tracker_only →
   …` (хранится, не используется), строка без оставшихся раздач получает `duplicate_of` (метка / заметка владельца и
   ручной ответственный копируются на настоящий тайтл); ничего не удаляется. Список — `python -X utf8 -m films.tracker_only
   list`; в отчёт владельцу — сколько создано, сколько опознано заново.
4. **Новые тайтлы** — метаданные (названия RU/UK, страны, жанры, длительность, студии, роли, режиссёр,
   сценарист, дата выхода), IMDb-рейтинг, RT (оба рейтинга; искать по оригинальному, латинскому, RU, UK названию),
   IMAX / мастер 2K-4K / бюджет / постер (IMDb GraphQL, без браузера): `python -X utf8 -m films.sources.imdb_specs run`
   (он же пишет `upscale_verdict` из мастера; **постер — по порядку IMDb → Rotten Tomatoes → TMDB → картинка со страницы
   раздачи**, владелец 2026-10-25: «TMDB — когда на IMDb и RT нет; а когда и там нет — с источников торрента»; полный прогон
   в конце сам вызывает `films.posters` — `docs/imdb-specs.md` «Постер»; картинки трекера (`poster_source = 'tracker'`,
   страница — `poster_release_id`) протухают и перепроверяются каждым обновлением: лучший источник → живая ли картинка →
   заново из кэша страниц / со свежей страницы rutor; отдельно — `python -X utf8 -m films.posters run`; после `ratings rt`
   его стоит повторить: постеры RT заменят TMDB / трекер); фильмам с 4K-раздачей и неизвестным мастером — blu-ray.com «Native/Upscaled 4K»
   (HTTP, ~7 с на запрос, фоном): `python -X utf8 -m films.sources.bluray_com run` (R32, `docs/research-codecs-upscale.md` §2.5);
   новое без TMDB — `python -X utf8 -m films enrich`, рейтинги — `films ratings imdb` и `films ratings rt`
   (`enrich` сам ищет TMDB по названиям + году, если TMDB не знает IMDb id, — только однозначное совпадение, см.
   `enrich.search_fallback`; найденный дубль чужой строки — issue `tmdb_same_as_title`); украинское название, если у TMDB
   его нет, — aka IMDb (`imdb_specs run` или отдельно `imdb_specs uk`, `title_uk_source`); монтажёр (role `editor`, только
   в БД) — в `enrich` и `title_meta editors`; правило IMAX поменялось — `imdb_specs imax` (только `is_imax`);
   **поля опроса метаданных** (владелец, 2026-10-25) — `python -X utf8 -m films.title_meta all` (после `enrich`; фоном, лог
   `data/logs/agent_title_meta.log`, всё докачивается с места остановки): ключевые слова, сайт, языки, мини-сериал, Wikidata →
   Википедия uk/en/ru, роли creator/dop/producer/composer (кэш TMDB), дистрибьютор / цвет / камеры / формат плёнки / места
   съёмок (IMDb GraphQL — проход `imdb` = `imdb_specs run`), русские и украинские имена людей, которых показывает таблица
   (TMDB /person + translations; Кинопоиск — никогда), даты покупки и добавления в список Google TV, дата добавления в Plex;
   полнота по полям — `python -X utf8 -m films.audit` (в отчёт владельцу);
   франшизы за все годы — `python -X utf8 -m films.franchise_releases` (потом снова pages/parse/match);
   русский трейлер: `python -X utf8 -m films.sources.youtube trailers` (короче 1:30 — тизер: штраф, ищется длиннее; не нашлось — `trailer_ru_check = teaser_only`), затем **аудит** `python -X utf8 -m films.trailer_audit --apply` (целые фильмы > 5 мин, недоступное в UA, трейлер другого фильма — снимаются; тизеры и несовпадение названий — в отчёт `data/cache/trailer_audit.json`);
   русский трейлер: `python -X utf8 -m films.sources.youtube trailers` (долго — фоном + сторож). Трейлер
   принимается, только если на странице ролика YouTube подтвердил русскую речь (язык дорожки / автосубтитров) либо
   название говорит «дубляж/озвучка»; русские субтитры к оригиналу и украинские трейлеры — отдельные находки, не
   трейлер. Правила — `docs/youtube.md`; спорные — `data/cache/youtube/ambiguous.jsonl`. Затем **обязательно** скил
   `trailer-check` (`films.sources.trailer_lang check --unconfirmed`): трейлеры без подтверждённой русской речи
   проверяются по субтитрам, альтернативам и звуку (распознавание речи).
5. **Перепроверить рейтинги** тайтлам, вышедшим за последние 90 дней, и тем, у кого рейтинга не было:

6. **rutracker** (Chrome, залогинен <rutracker.user>): для тайтлов, у которых на rutor нет 4K, нет HDR/DV или
   нет дубляжа — поискать там (по оригинальному и русскому названию), сохранить найденное.
   **«Максимальное качество» — альтернативу не искать** (R168(в), владелец 2026-10-25: «если раздача уже максимального
   качества — при обновлении базы альтернативу не искать; если там озвучка, а не дубляж — искать дубляж»):
   `rank.max_quality` — у лучшей раздачи тайтла **дубляж** (у сериалов Marvel / DC — **FlarrowFilms**, и вышли все серии
   сезона) **и** картинка лучшая из всех, в каких тайтл выходил: ни одна его раздача (любая озвучка, rutor и rutracker) не
   лучше по HDR, 4K и источнику (`rank.picture_key`), нет ремастера того же или большего разрешения, а если blu-ray.com
   разбирал 4K-диск (`upscale_source = bluray_com`), раздача ниже 4K — не максимум. Такие тайтлы `rutracker queries` не
   включает (`_needs` → пусто; строка `max_quality` в `rank.compute`); число таких тайтлов — в отчёте («Проблемы»).
   Сериалам Marvel / DC без полной раздачи FlarrowFilms запрос получает признак `flarrow` (сборщик отбирает темы со
   словом «Flarrow»). В таблице у такого сезона пометка «серий N из M с этой озвучкой» и строка «Все серии» ниже — с
   другой озвучкой, где серий больше (`rank.studio_episodes`); когда FlarrowFilms выпустят всё — строки «Все серии» нет.
   Как (2026-10-24, R150): **только Chrome** — встроенный браузер Claude Cloudflare не пропускает (проверка «я не робот»
   крутится по кругу даже после клика владельца). Читать без скриптов: `navigate` на `tracker.php?nm=…` → `get_page_text`;
   JS (`javascript_tool`) на rutracker каждый раз требует «Allow» владельца — только если без него никак, и сразу
   выгружать результат целиком (окно «Allow» истекает, переменные вкладки пропадают). Найденное — в
   `data/cache/rutracker/*.json`, затем в `releases`. Без окна «Allow» работают только `navigate` + `get_page_text`
   (номеров раздач в тексте нет); `find` / `read_page` / JS — с окном, поэтому весь сбор — одним JS-вызовом.
   **Запросы — по отдельности** (R151): оригинальное название, затем русское; не «RU + EN» одной строкой — слишком
   жёсткий фильтр, теряются раздачи с одним из названий.
   **Порядок запуска** (код — 2026-10-24: `films/browser/rutracker_collect.js`, `films/sources/rutracker.py`,
   разбор — `films/parse/rutracker.py` = парсер rutor на приведённой странице; тесты — `tests/test_rutracker.py`):
   1) после шагов 3–4 (rutor собран, разобран, связан): `python -X utf8 -m films.sources.rutracker queries`
      (`--extra "South Park" --extra "Южный парк"` — свои запросы; `--limit N` — только первые N; `--max-topics 40` —
      сколько страниц раздач открывать на запрос). Список: сезоны отслеживаемых сериалов без раздач (франшизы «все годы»
      с отсечками владельца, «хочу»), список «хочу» (R48), аниме франшиз (R44), затем R9 — видимые тайтлы, у лучшей раздачи
      rutor которых нет 4K / HDR-DV / дубляжа, в порядке таблицы. Пишет `data/cache/rutracker/queries.json` (с причинами),
      `queries_run.json` (отдаёт мост), `run.js` (сборщик + `__rtCollect({queriesUrl})`) и запасные `run_inline_N.js`.
      Объём (2026-10-24): ≈ 5 500 запросов (≈ 3 100 тайтлов R9) — несколько часов в фоне вкладки; поиск 1,5–2,2 с на запрос.
   2) мост — фоном: `python -X utf8 -m films bridge` (+ сторож: агент-watchdog).
   3) **один** вызов в Chrome (владелец у компьютера, жмёт «Allow» один раз): вкладка `https://rutracker.org/forum/index.php`
      (залогинен, без Cloudflare) → `javascript_tool` с содержимым `data/cache/rutracker/run.js` целиком. Вызов сразу
      возвращает «loading queries…»: дальше цикл идёт сам — поиск по всем страницам (до 500), страницы выбранных раздач
      (видео-форум, год ±1, в названии есть нужное: 2160p/4K, HDR/DV, Dub; уже известные не открываются), по POST на запрос
      в мост → `data/cache/ingest/rutracker-*.txt`. Прогресс видно по выводу моста (новые файлы); повторный JS не нужен.
      Остановка/проблемы: `__rtStatus()`, `__rtStop()` (каждый — ещё одно «Allow»). Вкладку не закрывать до конца
      (последний файл содержит `"final": true`), потом закрыть. Не залогинен / Cloudflare — цикл сам останавливается
      (`fatal` в отчёте ingest) → владелец логинится, повторить шаг 3 (известные раздачи не повторяются).
      Если мост недоступен из страницы (статус «no queries: …»): `run_inline_1.js`, `run_inline_2.js`… по одному вызову;
      неотправленное копится в `localStorage` → вычитать `__rtChunk(0)`, `__rtChunk(1)`… (`{i, n, data}`; `data` склеить
      в файл) → `ingest <файл>`.
   4) `python -X utf8 -m films.sources.rutracker ingest` (новые файлы моста; можно в процессе, повторно — идемпотентно) →
      `releases` (source='rutracker', ссылка на тему, размер, сиды, название), первый пост (описание + MediaInfo) →
      `release_raw`, поля качества/озвучки — тем же парсером, что rutor. DV5-only не сохраняются (`excluded_releases`).
      Затем `python -X utf8 -m films match` (или `ingest --match`). В отчёт: `capped` (запросы > 500 и после дробления),
      `error_samples` (`row_parse_failed` / `no_post_body` = поменялась разметка → поправить парсер, `… parse --reparse`),
      `dv5_already_stored`. `python -X utf8 -m films.sources.rutracker status` — счётчики.
