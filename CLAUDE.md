# Films — персональная база фильмов/сериалов/мультфильмов с 2024 года (без верхней границы)

Проект собирает **всю** базу зарубежных фильмов, сериалов и мультфильмов с 2024 года (без верхней границы) с торрент-трекеров,
обогащает её метаданными (IMDb, Rotten Tomatoes, TMDB, трейлеры), сверяет с Plex (что скачано / что просмотрено)
и магазинами (Google Play Фильмы / YouTube), а затем **скриптом** публикует отсортированную и отфильтрованную
таблицу, в которой владелец отмечает, что хочет смотреть.

Язык общения с владельцем — русский. Владелец: Plex `<plex.user>`, Google `<google.main>`,
YouTube-канал <youtube.channel_name> `<youtube.channel>`.

## Главные правила

**Работа с владельцем — скил [owner-rules](.claude/skills/owner-rules/SKILL.md)** (читать в начале сессии): внимательность,
вопросы только через AskUserQuestion, всё в план и скилы, работа без остановок, паузу — сначала в план, Plex/Google TV
только по его словам, сопоставление его списков, проверка перед ответом. **Всё по проекту — только в проекте**:
память Claude и глобальные скилы не использовать (хук `.claude/hooks/no-memory.sh`), личные данные — `config/private.toml`.

0. **Главный принцип — внимательность.** Ничего из того, что владелец попросил, не пропускать, не упрощать
   и не «экономить» (на запросах, страницах, проверках, токенах). Если что-то не удалось — явно сказать что
   и почему, записать в PLAN.md, а не тихо обойти. Каждый тайтл проверяется полностью по всем полям.
   Для сайтов, закрытых от curl (rutracker, IMDb, Google Play, YouTube-аккаунт), использовать
   **Chrome (Claude in Chrome)** — он доступен и залогинен под владельцем.
1. **БД — единственный источник правды.** Таблица (Google Sheets) только *генерируется* из БД скриптом.
   Ручные пометки владельца в таблице (цвет-метка, заказчик, заметка) перед каждой перегенерацией
   **сначала считываются обратно в БД**, потом таблица пересоздаётся. Никогда не перезаписывать таблицу,
   не прочитав пометки.
2. **Ничего не удалять из БД.** «Фильтр» = флаг/исключение при выгрузке, а не DELETE.
   Единственное исключение — раздачи, у которых *только* Dolby Vision Profile 5 (без HDR10-фолбэка):
   их не сохраняем вообще (у владельца DV5 не поддерживается).
3. **Сохраняй сырые данные**, чтобы не переоткрывать оригинальные ссылки: сырой текст страницы раздачи
   (описание + MediaInfo) кладём в кэш-таблицу `release_raw`. Новые поля потом извлекаются из кэша.
4. **Новый повторяющийся тип метаданных** (которого нет в схеме) — спроси владельца, нужен ли он,
   прежде чем отбрасывать или сохранять. Записывай ответ в раздел «Решения» ниже.
5. Действия от имени владельца во внешних сервисах (Plex «просмотрено», вишлист Google Play,
   плейлист YouTube) выполняются только по его запросу через соответствующий скил.
   Постоянное поручение владельца (2026-10-23): **всё, что просмотрено в Jellyfin, обязательно отмечается в Plex**
   (сервер + аккаунт) — `films watched from-jellyfin` при каждом «обнови базу» (скил `update-db`) и по запросу.
   **Отметка «просмотрено» в Plex — только по словам владельца** («я видел X» или его постоянное поручение, как
   перенос из Jellyfin). Ничто другое (купил, скачал, было в старой таблице, догадка) поводом для отметки не служит.
   **Никогда не отмечать повторно уже просмотренное** — это пишет в историю Plex сегодняшнюю дату и ломает хронологию
   владельца (баг 2026-10-23). Закреплено кодом: все запросы в Plex идут через `films/sources/plex_guard.py`
   (уже просмотренное и сезон целиком — отказ; снятие отметок и удаление из истории — только по списку, подтверждённому
   владельцем), а хук `.claude/hooks/plex-guard.sh` блокирует обходные команды и правку предохранителя.
   То же для **списка просмотра Google TV** (владелец, 2026-10-24: «не надо, как в Плексе, сбрасывать то, что было добавлено
   по дате»): кнопка «Хочу посмотреть» переключается — нажатие на уже добавленном фильме удаляет его. Добавлять только через
   `films/browser/gtv_watchlist_guard.js` (`__gtvGuard.add`: жмёт лишь при `aria-pressed=false`, проверяет фильм и год,
   сверяет результат); из списка ничего не удалять. Хук `.claude/hooks/gtv-guard.sh` блокирует прочий JS/клики по списку и правку предохранителя.
6. Секреты (токены, ключи, OAuth) — только в `.env` / `secrets/` (в `.gitignore`), **никогда в git**. Хранилище секретов
   для переноса на другие машины — заметка Google Keep «films — секреты» аккаунта **<google.cloud>** (это тоже
   владелец; доступ к нему есть у всех, кто ведёт проект). Подробно — [docs/google-setup.md](docs/google-setup.md). Plex-токен читается
   из реестра Windows (`HKCU\Software\Plex, Inc.\Plex Media Server\PlexOnlineToken`), в файлы не пишется.

## Открытый репозиторий: секреты и личные данные

Репозиторий публичный. В git **никогда** не попадают:
- секреты — `.env` (TMDB-ключ), `secrets/` (OAuth-клиент Google, токены), Plex-токен (он только в реестре);
- личные идентификаторы — почты и логины владельца, ID приватных списков, ID Plex-сервера, имя/телефон/адрес →
  файл `config/private.toml` (в `.gitignore`; шаблон — `config/private.example.toml`). В документах и скилах вместо
  них метки `<google.main>`, `<google.cloud>`, `<plex.user>`, `<rutracker.user>`, `<tmdb.user>`, `<youtube.channel>`,
  `<youtube.channel_name>`, `<google_tv.watchlist_url>`, `<plex.machine_id>`, `<jellyfin.user>`, `<owner.name>`; код читает их через
  `films.db.private()`;
- чужие почты (владельцы чужих проектов и т.п.) — не записывать вообще.

Где лежат значения: заметка Google Keep «films — секреты» аккаунта `<google.cloud>` (там `.env`, `secrets/*`,
`config/private.toml`). На новой машине — восстановить из заметки ([docs/google-setup.md](docs/google-setup.md)).

**Скрывать что-либо — только спросив владельца, что скрывать, а что нет** (владелец, 2026-10-24: «перед действием о сокрытии ты меня будешь спрашивать, что скрывать, а что нет»; личные видео владельца — в git не публикуются (исключены из копии `backup/` и `data/plex_show_map.json`), в локальной базе — временно: «они там на пару дней … это гит-игнор одной недели, через неделю не забыть удалить» — удалить 2026-10-31). Копия базы для git (`backup/`) — без путей к личным файлам и имени пользователя Windows (`backup._redact`); имена близких, «Костя», логин GitHub — можно (владелец, 2026-10-24); подробно — скил owner-rules §9.

Перед каждым пушем: `python -X utf8 -m films privacy-check` (стоит и в `.git/hooks/pre-push`) — ищет значения из
`private.toml`, почты и похожие на ключи строки во всех публикуемых файлах **и в БД**. Новые личные данные —
сначала в `private.toml`, потом метка в тексте.

Поиск тайтлов на внешних сайтах — **всегда минимум по оригинальному и латинскому названию**, затем по русскому и украинскому.

**Экономия подтверждений (просьба владельца):** никакой поштучной работы в браузере по тысячам тайтлов.
- IMDb-рейтинги и голоса — **только из датасетов** (`title.ratings.tsv.gz`, один файл на все тайтлы, без браузера).
- Тех. характеристики IMDb — через GraphQL по HTTP, Chrome для IMDb не нужен.
- rutracker — тоже пачками и только для тайтлов, которым на rutor не хватает 4K / HDR-DV / дубляжа.
- Одиночный тайтл (например, «я видел X» или проверка одного фильма) — можно просто открыть страницу.
- Каждый JS-вызов в Chrome на новом сайте показывает владельцу окно подтверждения. Параллельным агентам
  Chrome давать **только** если их задача без него невыполнима, и явно перечислять, на каких сайтах.
  Прежде чем говорить владельцу, кто сейчас работает в Chrome, — проверить, а не отвечать по памяти.
- **В Chrome одновременно работает только один агент/сессия**: у всех общая группа вкладок, параллельные
  агенты ломают друг другу группу и оставляют вкладки, которые потом не закрыть (2026-10-23).
- **Закрывать за собой вкладки Chrome**, как только они не нужны (и пустые «Новая вкладка» тоже). Агентам передавать это правило в задании.

**Сторож фоновых агентов (владелец, 2026-10-23): раз в 30 минут проверять, что агенты не зависли.**
- Запустил фоновый агент или долгую фоновую команду → сразу `CronList`; если задачи проверки нет — `CronCreate`
  (recurring, «13,43 * * * *»). Напоминание даёт хук `PostToolUse` на `Agent` (`.claude/settings.json` →
  `.claude/hooks/agent-watchdog.sh`).
- Проверка: хвост `tasks/*.output` каждого агента/команды и прогресс с прошлой проверки. 30+ минут без вывода
  или по кругу → `SendMessage` агенту → не помогло: `TaskStop` и перезапуск с уточнённым заданием, запись в PLAN.md.
  Короткий итог владельцу: кто работает, кто закончил, кто завис.
- Cron срабатывает только когда сессия простаивает → дублирует его PostToolUse-хук `.claude/hooks/watchdog-tick.sh` (раз в 30 мин и посреди хода: `python -X utf8 -m films.watchdog` — процессы, свежесть логов, «ЗАВИС?»; Chrome-циклы — `__plRun` / `__gRun` в вкладке).
- Хук `agent-watchdog.sh` (PostToolUse на Agent, фоновые Bash/PowerShell, CronCreate/CronDelete) помнит таймер в `data/cache/locks/watchdog_cron.json` и **блокирует** любой фоновый запуск без таймера (владелец, 2026-10-25: «чтобы он при любом запуске агента опять запускался»).
- Фоновых агентов не осталось → `CronDelete`. Cron живёт только в сессии (и не больше 7 дней): в новой сессии
  с запущенными агентами взвести заново.

**Параллельно и с семафорами** (владелец, 2026-10-24): независимые шаги запускать параллельно (фоном), критические секции — через `films/locks.py`: `lock(name)` — исключительный доступ между процессами, `pace(name, s)` — общий интервал запросов. Уже под ними: запись в Plex (`plex_write`, ≥ 1 с), YouTube (`youtube_http`), пересборка таблицы (`sheet`). Список Google TV и Chrome — один цикл / один агент (два цикла кнопки «Хочу посмотреть» = удаление).

**Сбор через Chrome массово:** открыть вкладку на нужном домене и выполнять `fetch()` того же домена из
`javascript_tool` пачками; результаты отправлять в локальный приёмник `python -m films bridge`
(`http://127.0.0.1:8765/ingest/{kind}`, CORS + Private-Network заголовки), который пишет их в БД.
Так данные не проходят через контекст. (Механизм проверяется в PLAN.md, этап 2.)

## Модель данных (SQLite, `data/films.db`)

Схема — в [films/db.py](films/db.py). Кратко:

- `titles` — тайтл (фильм / сериал / мультфильм): названия (orig/ru/uk), год, дата выхода, страны, жанры
  (`main_genre` = первый жанр), длительность, студии, IMDb/TMDB/RT id, рейтинги (IMDb, RT critics, RT audience),
  ссылка на русский трейлер, `is_imax`, `no_dub_needed` (ручной флаг «озвучка не нужна»).
- `people`, `credits` — люди и роли (актёр/режиссёр/сценарист/…).
- `releases` — раздачи с трекеров: источник, ссылка, btih, размер, сиды, разрешение, тип исходника
  (BDRemux/BDRip/WEB-DL/…), HDR (DV / HDR10+ / HDR10 / HLG), профиль DV, аудиодорожки (язык, тип перевода,
  студия), субтитры, сезон/серии.
- `release_raw` — сырой текст страниц раздач (кэш, чтобы не ходить повторно).
- `plex_items` — что лежит в Plex: библиотека, путь, качество файла (разрешение, HDR/DV, аудио).
- `watched` — что просмотрено (источник: `plex` / `jellyfin` / `manual`; `*_partial` — сезон досмотрен не до конца, «видел» не считается).
- `jellyfin_items`, `jellyfin_played` — файлы Jellyfin с id и отметки «просмотрено» владельца.
- `user_marks` — пометки владельца из таблицы (метка-цвет, заказчик, заметка).
- `responsibility` — кто ответственный за решение смотреть (сейчас: Дима — комедии).
- `store_status` — Google Play / YouTube: куплено, в желаемом, цена, скидка, недоступен.
- `events` — что изменилось за прогон «обнови базу» (новые тайтлы, раздача в лучшем качестве, вышел дубляж…).
- `runs` — журнал прогонов.

## Фильтры (исключают из основной таблицы, но не из БД)

- просмотрено (Plex / plex.tv / ручная отметка);
- владелец сказал «не интересен» (`user_marks.mark = 'not_interested'`) — скрыть; в листе «Все» видно с причиной;
- скачано в Plex (даже не просмотренное) — **кроме** случаев, когда доступно лучшее качество (тогда строка наверху, 🟢);
- IMDb < 5.0 **и** дата выхода старше 30 дней (свежие с низким рейтингом остаются);
- нет никакой озвучки (ни RU, ни UK, ни многоголоски/авторской) — кроме тайтлов с `no_dub_needed = 1`;
- раздачи только с DV Profile 5 не сохраняются вовсе.

## Сортировка основной таблицы

Владелец, 2026-10-24: **баллы за каждый признак**, не простая цепочка. Лучшая раздача тайтла — сначала озвучка-приоритет сериала (`[voice_preference]`, напр. «Рик и Морти»: Кубик в Кубе / Сыендук), затем общий порядок. Порядок строк:

1. **ТОП** — `[top] imdb` в `config/settings.toml`, в порядке, названном владельцем («в топ над всем»); без трейлеров.
2. **Срочно** — 🟢 «обязательно скачать», 🧞‍♀ заказы, ❤️ без галочки для «Костя Хочет» (`responsible.urgent_titles`).
3. Остальное — **по сумме баллов** (`[sort.weights]`, `rank.compute`; разбивка по признакам — лист «Баллы»):
   список владельца ❤️ 300 / 💛 200 / без смайлика 100, «хочу» (сериалы) 250, апгрейд 150, франшиза 120, IMAX 100,
   новинка с высоким RT ❤️ 90 / 💛 70 (R99), новинка с 2026 по дате на rutor 40, важные люди до 90, HDR, 4K 25, озвучка,
   желаемое 15, IMDb 10/балл выше 5, RT 0,3/балл выше 50. При равенстве — старая цепочка `[sort] order`
   (апгрейд → франшиза → IMAX → люди → HDR → 4K → озвучка → желаемое → IMDb).
Веса владелец согласует «в самом конце» (R108). Плейлисты — в том же порядке (`playlist_notes.visible_order`).

## Строки одного тайтла в таблице (варианты)

**Сериал = отдельный тайтл на каждый сезон** (своя строка в БД и таблице, свой рейтинг RT, свой статус «видел»,
скачано, ответственный). Сезоны не объединять: владелец может видеть 1-й и не видеть 2-й.

В БД хранятся **все** раздачи; в таблице у тайтла (фильма или сезона) максимум такие строки, **подряд**
(сортировка по ключу основной строки):

1. **Лучшее** — лучшая раздача: **сначала озвучка** (дубляж > проф. многоголосый > … — «дубляж важнее качества всегда», владелец 2026-10-24), затем HDR/DV, 4K, источник, битрейт (`rank.release_key`). Оригинальный Dolby Vision
   предпочтительнее пересобранного из HDR10 (статические метаданные); если есть только пересборка — пометка
   «DV: статические метаданные».
2. **Open Matte** — если есть.
3. **Расширенная / режиссёрская** — если есть.
4. **Оригинал без апскейла** — если 4K в «лучшем» — студийный апскейл (мастер 2K): строка с лучшим
   НЕапскейленным релизом (BDRemux 1080p, а если его нет — лучший 1080p из имеющихся). Апскейл определяется
   только по внешним источникам (IMDb tech specs Digital Intermediate, blu-ray.com Native/Upscaled, продажи дисков) —
   трекеры этого не пишут.
5. **AI-апскейл** — фанатские апскейлы: одна строка с лучшим из апскейлеров. Остальные апскейлы — только
   по запросу владельца в чате.

Все раздачи во всех качествах **не показывать** — только эти варианты.

## Листы/выходы

- **Главная / Сериалы / Мультфильмы / Мультсериалы / Аниме** — отфильтрованные и отсортированные тайтлы.

| Скил | Когда | Что делает |
|---|---|---|
| `update-db` | «обнови базу» | новые раздачи → тайтлы → метаданные/рейтинги → Plex (скачано/просмотрено) → апгрейды → таблица → отчёт об изменениях |
| `mark-watched` | «я видел X», «посмотрел X» | находит тайтл, отмечает просмотр в Plex, в БД, ставит в очередь вишлиста, обновляет таблицу |

## Команды

```bash
python -m films init-db          # создать/мигрировать схему
python -m films status           # сводка по БД
python -m films update --start   # «обнови базу»: открыть прогон (снимок состояния)
python -m films update --finish  # события, дата обновления, отчёт об изменениях
python -m films.encountered collect          # раздачи за любые годы для всего, что встречается
python -m films.sources.qbittorrent owned    # раздачи из адресов в торрент-файлах владельца
python -m films.sources.rutracker queries    # rutracker: список запросов (сбор — один JS-вызов в Chrome)
python -m films.bridge                       # локальный приёмник данных из Chrome
```
Остальные команды появляются по мере реализации — см. PLAN.md. **Код с обратной косой (`\b`, `\d`, пути Windows) — только инструментом Edit/Write, не через python-heredoc в bash**: там `\b` превращается в управляющий символ (так ломались шаблоны DV/4K, путь в `disk_map.json`, хук вопросов — 2026-10-25); ловит `tests/test_source_hygiene.py`. Все скрипты: Python 3.12, зависимости в
`requirements.txt`. На Windows запускать с `-X utf8` или `PYTHONUTF8=1` (консоль cp1251 ломает кириллицу).
