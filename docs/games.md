# Игры владельца → экранизации (R36)

Реализация от 2026-10-23. Модуль: `films/sources/games.py`. Таблицы: `games`, `game_adaptations` (миграция 7).
Кэш сырых ответов: `data/cache/games/` (в `.gitignore`), по файлу на запрос; итог последнего прогона —
`data/cache/games/collect_notes.json` и `adaptations_summary.json`.

```bash
python -X utf8 -m films.sources.games collect [--store playstation|steam] [--max-age ДНЕЙ]
python -X utf8 -m films.sources.games import playstation|steam ФАЙЛ   # список, выгруженный владельцем
python -X utf8 -m films.sources.games adaptations [--no-wikipedia] [--max-age ДНЕЙ]
python -X utf8 -m films.sources.games report [--json]
```

Идентификаторы аккаунтов — в `config/private.toml`, секция `[games]`: `<games.ps_store_db_url>`,
`<games.steam_id>`, `<games.steamdb_url>`. Код читает их через `films.db.private()`, в выводе и логах они
заменяются на `<private>`, в БД не пишутся (в `games.raw` — только id игр, названия, часы, где игра встретилась).
Ник PSN / vanity-имя Steam, которые видны на страницах, тоже никуда не сохраняются.

## Доступ к источникам (только HTTP, без браузера)

### PlayStation — ps-store-db.live

- `<games.ps_store_db_url>` — публичная страница профиля, отдаётся сервером (HTML, без JSON-API).
  На ней только **витрина**: «Where the hours went» (топ-9 по часам), первые игры PS3/PS4/PS5, первая и
  самая редкая платина, полоски значков (badges). Это ~24 названия из «N games played» (на 2026-10-23 — 361).
- Полный список игр («hub»: бэклог, списки, сделки) сайт показывает **только в браузере, который построил
  страницу** (сессионная cookie, `GET /api/hub/me` → без cookie `{"hub": null}`). На странице так и написано:
  «The backlog, deals and list tools only appear in the browser that built this page».
  `GET <url>/games` → 405, `<url>/backlog` → 302 на саму страницу.
- Это список **сыгранного** (данные трофеев PSN), а не покупок. Покупки PS Store без входа в аккаунт Sony
  не видны нигде.
- Сторонние PSN-базы проверены: psnprofiles.com и psntrophyleaders.com — Cloudflare challenge (не обходим),
  exophase.com — профиля нет (404).
- `games.game_id` = `title:<нормализованное название>`; в `raw` — `seen_in` (раздел витрины), часы, id из
  ссылки на картинку (CUSA/NPWR…), `note: played, not necessarily purchased`.

**Как получить полный список** (нужен владелец):
1. В браузере, где строилась страница, открыть хаб и выгрузить список (или прислать скриншоты/текст) →
   `import playstation файл.txt` (по названию в строке) или JSON `[{"title": …}]`.
2. Либо на этой странице «Page settings → Move this page to another browser» даёт одноразовый код переноса;
   ввод кода (`POST /profile/claim`) **перенесёт** хаб в другой браузер — это действие от имени владельца,
   без его решения не делаем.

### Steam

- `https://steamcommunity.com/profiles/<games.steam_id>/games?tab=all&xml=1` и `/games/?tab=all` —
  **редирект на страницу входа** для анонимного посетителя (проверено и на чужом публичном профиле —
  это общее правило Steam, а не настройка приватности владельца).
- `IPlayerService/GetOwnedGames` без ключа → 401. Если в `.env` есть `STEAM_API_KEY` (бесплатный ключ
  владельца, https://steamcommunity.com/dev/apikey), `collect` берёт **всю** библиотеку через Web API
  (ключ не печатается и не пишется в кэш-URL).
- Без ключа собирается **публичное подмножество** (профиль открыт):
  - страница профиля: размер библиотеки (601 игра, 736 DLC на 2026-10-23), любимая игра, недавняя
    активность, витрина достижений;
  - все страницы обзоров `/recommended/?p=N` (104 обзора; обзор можно написать только на продукт из
    библиотеки) — app id, часы, «куплено в Steam».
- Названия и тип (game / dlc / mod / application) — `store.steampowered.com/api/appdetails`; если игры нет в
  магазине — заголовок страницы `steamcommunity.com/app/<id>`.
- SteamDB (`<games.steamdb_url>`) — Cloudflare challenge (403), не обходим; Steam Ladder отдаёт только
  счётчики (596 игр, часы), без списка; SteamHunters, completionist.me — Cloudflare; AStats — таймаут.
- Пауза 3 с между запросами к steamcommunity.com (он быстро отвечает 429), backoff по `Retry-After`.

## Экранизации

1. **Игра → элемент Wikidata.** Steam: по app id (P1733) — точно (если у одного app id несколько элементов —
   оригинал и переиздание, — берутся все: `matched_multi`). Остальное (PlayStation, импорт):
   полнотекстовый поиск Wikidata (`EntitySearch` через WDQS), берём только элементы-видеоигры
   (P31/P279* Q7889) с точным совпадением нормализованного названия или алиаса; издания («Remastered»,
   «Game of the Year Edition», «6th Anniversary», ™®) отрезаются. Несколько кандидатов → платформа магазина
   (PS4/PS5/PS3 или Windows) как разрешитель, затем точное название из магазина до отрезания издания; если всё равно несколько — `ambiguous` (в отчёт), но если все
   кандидаты из одной серии игр, экранизации считаются по всем (от выбора не зависят). Результат лежит в
   `games.raw.wikidata`.
2. **Узлы:** сама игра; её серия (P179, два уровня); медиафраншиза (P8345, и у серии); вымышленная вселенная
   (P1080); соседние игры той же серии; то, на чём основана сама игра или серия (P144: книги, игрушки,
   фильмы) — связь `same_source`, всегда `review` (так находится «Ведьмак» Netflix: и игры, и сериал
   основаны на книгах Сапковского).
3. **Экранные произведения** (фильм, сериал, мини-сериал, веб-сериал, анимация; не эпизоды/сезоны/«серия
   фильмов»/трейлеры; порнопародии — жанр P136 Q185529 / Q16254232 — выбрасываются и перечисляются в
   `skipped_adult_parodies`): P144 «основано на» → узел (или серия фильмов, основанная на узле), либо общая серия /
   франшиза / вселенная (P179 / P8345 / P1080).
4. **Википедия en/ru:** статьи игры и её игровой серии (список разделов `action=parse&prop=sections`, затем
   викитекст только подходящих разделов — маленькими запросами), разделы «Adaptations», «Film», «Television»,
   «In other media», «Экранизации», «В других медиа», «Фильмы», «Сериалы»… (с подразделами): ссылки и
   шаблоны `{{Main|…}}` → Wikidata (sitelinks через WDQS, редиректы через API) → только экранные произведения;
   «серия фильмов» / франшиза раскрывается в свои части (P527 / P179).
   **Фильтр шума:** разделы «Other media» ссылаются и на другие фильмы режиссёра/сценариста, камео,
   «похожее» (God of War → «Пила», «Тихоокеанский рубеж»). Ссылка, которой нет в Wikidata для этой игры,
   сохраняется, только если в названии произведения есть название игры / её серии / игровой франшизы;
   остальные **не пишутся в БД**, а перечисляются в `adaptations_summary.wikipedia_unconfirmed` и в конце
   `report` («Wikipedia links NOT stored … check by hand») — там же настоящие находки без названия игры
   в заголовке (Bright Falls ← Alan Wake, Captain Laserhawk ← Assassin's Creed) для решения владельца.
5. **Франшиза из игр или нет.** Франшиза / вселенная считается игровой, если Wikidata типизирует её как
   серию/франшизу видеоигр или самый ранний датированный её элемент (P8345 / P1080 / P179 → франшиза) —
   видеоигра (Resident Evil: игра 1996 < фильм 1998…; годы — в `adaptations_summary.franchise_origin`).
   **Франшизы не из игр** (Star Wars, Marvel…): связь «общая франшиза» — `review`;
   если у такой франшизы больше 25 экранных произведений, она пропускается целиком и перечисляется в
   `adaptations_summary.skipped_big_franchises`.
6. **IMDb id:** P345; без него — TMDB id из Wikidata (P4947 / P4983) → `external_ids` через
   `films/sources/tmdb.py`; нет и там — `imdb_id = 'wd:Q…'` (видно в отчёте).

`game_adaptations.sources` (JSON): `relation` (based_on_game / based_on_series / based_on_series_game /
game_franchise / shared_franchise / wikipedia_section / …), `confidence` (`confirmed` — прямая связь в Wikidata;
`review` — только Википедия или общая франшиза не из игр), `via` (узлы), `found_in`, `wikipedia_sections`,
`work_qid`, `game_qid`, `title_ru`, `group` (собственная серия игры (P179) → игровая франшиза → сама игра;
по ней группируется отчёт), `imdb_how`, `types`. Названия: метка `en`, иначе языконезависимая `mul`
(Wikidata переносит туда многие метки).

Строки только добавляются/обновляются (upsert), не удаляются. Строка, которую очередной прогон не
подтвердил, получает `sources.stale = <дата>` и в отчёт не попадает.

## Отчёт

`report`: игры по магазинам и заметки сбора (что заблокировано), сопоставление с Wikidata, игры с
экранизациями, список «франшиза → произведения» (год, тип, IMDb id, есть ли в `titles`, отмечено ли в
`watched`, `[REVIEW]` для сомнительных), игры без сопоставления с кандидатами. `--json` — то же машинно.

## Ограничения (на 2026-10-23)

- Запросы к Википедии идут **новым соединением каждый раз**: keep-alive сессия `requests` залипала на узле
  Varnish, который на всё отвечал 429 «robot policy», а новые соединения проходили (2026-10-23).
- Wikimedia action API (Википедия + www.wikidata.org) — одна корзина лимита; без `FILMS_CONTACT` в `.env`
  это 10 запросов/мин (`films/franchise.py`), и параллельный прогон `films.franchise` выбирает её целиком:
  2026-10-23 запросы к Википедии получали Varnish 429 «robot policy» подряд. Поэтому поиск игр идёт через
  WDQS, Википедия — маленькими запросами с ожиданием; страницы, которые так и не удалось прочитать,
  перечислены в `adaptations_summary.wikipedia_notes` (повторный `adaptations` дочитает их из кэша + сети).
  Лучшее решение — `FILMS_CONTACT` в `.env` (контакт в User-Agent → ~200 запросов/мин).
- Неполные списки игр (см. выше): PlayStation — витрина ~24 из 361, Steam — ~110 из 601 без ключа.
