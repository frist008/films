# Старая таблица владельца (`<legacy.sheet_url>`)

Старая Google-таблица, где владелец годами вёл фильмы/сериалы/франшизы «что посмотреть». Ссылка — только в
`config/private.toml` → `[legacy] sheet_url` (в git не попадает). Разобрана 2026-10-23 только на чтение
(ничего не редактировалось, версии не восстанавливались, доступ не менялся).

## Что в ней

- Листы: `Дима` (раньше `Лист1` → `Д`), `Саня` (создан 2026-08, раньше `С`), `Стас` (2026-08). Других листов не было
  ни в одной версии (список листов прочитан в каждой ревизии).
- Колонки — категории, а не поля: `DC`, `Marvel / Disney`, `Другое (…)`, в ранних версиях `Marvel`,
  `Юрские период`, `Джеймс Ван Хронолгия…`. Год, если есть, — внутри названия; пометки — в скобках
  («Комедия», «Атмосфера», «N серии = 1 долг» и т.п.).
- Значение — цвет заливки ячейки. Легенда есть только на листе `Саня`: красный «Очень горит», светло-красный
  «уже можно смотреть следующую часть», светло-жёлтый «скоро выйдет следующая часть», бледно-зелёный «Смотреть с …,
  следующая часть тоже уже доступна». На листе `Дима` цвета без легенды.
- История: ревизии 1…2011, 2023-03-24 … 2026-10-02; 155 записей в «Истории версий», 741 подробная ревизия,
  именованных версий нет.

## Как извлекали (Chrome, одна вкладка на docs.google.com, `fetch` из страницы)

1. Текущая версия: `…/htmlview/sheet?headers=true&gid=<gid>` — HTML с классами стилей → текст и цвета ячеек.
   (`gviz/tq?tqx=out:csv` тоже работает, но без цветов и может терять значения в колонках смешанного типа.)
2. Список ревизий: `…/revisions/tiles?id=<id>&start=1&revisionBatchSize=1500&showDetailedRevisions=true|false&token=<t>`
   (ответ с префиксом `)]}'`; отдаёт порцию до 1500 ревизий от конца и `firstRev` — для более старых повторить с
   `end=firstRev-1`). `token` — строка вида `…:<число>` из инлайн-скриптов страницы редактора.
3. Содержимое ревизии: `…/revisions/show?rev=<N>&gid=<gid>&token=<t>` — полный HTML листа на ревизии N
   (несуществующий gid → первый лист). С `&fromRev=<M>&scr=true` — сжатый дифф, в конце которого JSON-список листов
   ревизии `[{…, индекс, gid, имя, [изменённые диапазоны]}]`.
4. Обход: для каждой из 741 подробной ревизии — дифф (`scr=true`) → список листов и какие изменились → полный `show`
   только изменённых листов → объединение всех ячеек (gid, строка, колонка, текст, стиль) с номерами ревизий.
   Переносы строк внутри ячеек (`<br>`) нужно заменять на `\n` до `textContent`.
5. Передача на диск: Chrome→localhost блокируется запросом Local Network Access, скачивание требует разрешения
   владельца — поэтому данные выводились текстом (страница на docs.google.com + `get_page_text`, ≤50 000 символов
   за раз) и сохранялись вручную. Поэтому сохранено объединение по всем ревизиям, а не CSV на каждую версию.

## Результат (`data/cache/legacy_sheet/`, в `.gitignore`)

- `manifest.json` — что прочитано, ограничения.
- `current_<лист>.csv`, `current_<лист>_colors.csv`, `raw/current_htmlview.json` — текущая версия с цветами.
- `raw/history_items.txt`, `history_items.csv` — каждая встречавшаяся ячейка: первая/последняя дата, есть ли сейчас,
  колонка, последовательность цветов.
- `raw/dump_meta.tsv`, `raw/dump_texts.tsv` — ревизии, листы по ревизиям, все тексты.
- `items.json` — 564 записи (ячейки) → 347 произведений: ручное сопоставление названия с произведением
  (`work/works.py`; спорные — с пометкой «предположение»), затем `films.sources.tmdb.search` → TMDB id, IMDb id,
  коллекция TMDB; сравнение с `titles`, `watched`, `config/franchises.toml` и `franchise_members`
  (без строк `confidence = 'review'`). БД не изменялась: ответы TMDB читались из кэша `tmdb_raw` только на чтение,
  новые кэшировались во временный файл.

Итоги сверки и вопросы владельцу (новые кандидаты во франшизы, фильмы, которых нет в БД) — в PLAN.md / отчёте сессии.
